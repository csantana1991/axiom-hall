[[BEAT 0]]
A count-min sketch is a grid of counters. The grid has depth d and width w. Each row has its own hash. An arrival increments one cell per row, the cell the row’s hash names, and no other cell moves. The query returns the minimum across the d cells the item maps to. Because the updates you are allowed to make here are positive, every cell an item touches is at least the true count, so the minimum is at least the truth. That one-sidedness is the property the lab exists to show. It is not, by itself, the calibrated error you will size in the next beat.

Watch a single arrival before you watch a collision. A symbol arrives once. For each row, you evaluate that row’s hash, you land in one column out of w, and you add one to that cell. If the depth is four, four cells increase, one in each row. The other cells in those rows stay as they were. If the symbol has never been seen and no earlier symbol hashed into those four cells, each of the four cells moves from zero to one. The query takes the minimum of those four cells and returns one. The truth is one. The minimum matches. Nothing in that story required the hashes to be cryptographic. It required them to name a column.

Now put a second symbol in, and let it collide in one row, because collisions are the point of the lab and a hash that never collides on eight keys is a lookup table in a costume. The alphabet in the lab is those eight futures roots. Suppose the depth is two and the width is four. That grid has eight cells. It is a picture, not a calibrated sketch, and you will not attach an epsilon to it. Let symbol A arrive five times, and let symbol B arrive three times. The truth for A is five. The length of this tape, the first moment, is eight. Suppose row zero sends A and B to the same column. That cell was incremented five times for A and three times for B, so it reads eight. Suppose row one sends them to different columns. A’s cell in row one reads five, and B’s cell reads three. The query for A takes the minimum of eight and five, which is five. The collided row lied, in the sense that eight is not the truth. The clean row did not. The minimum discards the lie. That is the whole rescue the query is designed to perform.

The same grid, with a worse hash, shows you the one-sided error without the rescue. Suppose row one also sends A and B to one column. Then both of A’s cells read at least eight. The minimum is eight. Eight is greater than five. The estimate is still at least the truth. A minimum of overestimates is still an overestimate. You have not found a counterexample to the claim. You have found a collision pattern the depth failed to cover. Adding a third row that happens to keep A alone would pull the minimum back to five, if that row’s cell reads five. The minimum does not average the rows. It does not vote. It takes the smallest. Averaging eight and eight and five would invent a number the algorithm does not return. The formula is the minimum over rows of the cell the row’s hash selects.

Change one input. Keep the two-by-four picture and the collision pattern where only row zero collides, and change A’s arrivals from five to six. B stays at three. The truth for A is six. The collided cell reads nine. The clean cell reads six. The minimum is six. The floor moved with the truth. The overestimate in the dirty cell grew by one as well, because A’s extra arrival hit every row, including the dirty one. A collision inflates a cell. It does not exempt that cell from counting the true arrivals. That is why the cell cannot fall below the truth while updates stay nonnegative: every true arrival increments it, and collisions only add more.

You might ask whether the minimum could still undershoot if a row’s hash forgot one of the arrivals. Only if the update rule was broken. The update says that for each row, the named cell increases by one, and no other cell moves. Forget a row and you no longer have this algorithm. Increment by one on each arrival and the touched cell is a sum of the true count and the collisions. A sum of the true count and a nonnegative collision count is at least the true count. The minimum of several such sums is at least the true count. The argument is that short. It does not need the width to be four or the depth to be two. Those sizes were a picture so you could add five and three by hand. The argument survives when the grid is large enough to carry a real epsilon, and it survives when the grid is too small to cash one.

What the one-sided claim does not mean is that the estimate is exact, or that a larger estimate is a malfunction you should patch by subtracting. Eight against a truth of five is the algorithm working as analyzed, on a bad draw of the hashes. Subtracting three because you happened to know B’s count uses knowledge the sketch is not given at query time. On the toy, you do know, because eight roots fit on the screen and the truth is visible. That knowledge is the audit. It is not a step in the query. The query returns the minimum. If you “correct” it with the true collision count, you have stopped querying the sketch and started using the tape. What the claim also does not mean is that you may add negative updates quietly. A decrement can pull a cell below the truth. The moment a cell can fall below, the minimum can fall below, and the one-sided argument is gone. If you need deletions, you need a different structure and a different proof. You do not borrow this one.

Walk the decrements explicitly so the break is a number and not a warning sign. Start from the rescued picture: row zero holds eight for A and B together, row one holds five for A. The minimum is five, matching the truth. Now suppose you are tempted to retract B’s three arrivals by subtracting three from every cell B touches. B shares row zero’s cell, so that cell falls from eight to five. B’s own cell in row one falls from three to zero. A’s clean cell stays at five. The minimum is still five. This particular retraction happened to land on the truth. Change the collision so that some earlier, unrelated symbol C had also added two into A’s clean cell before you understood the tape. Then the clean cell would have read seven, not five, and a clumsy global repair is no longer available. Worse, subtract from a cell A touches without a matching collision story: take the clean cell from five down by one, to four, because a negative update hit it. The minimum of the dirty cell and four is at most four, and four is below the truth five. The lab’s rule is the practical form of this arithmetic. If any estimate goes below the truth, the lab is broken. A quiet decrement is enough to break it.

The hashes in that picture are part of the algorithm, and the lecture tells you what kind they are. The lab uses tiny linear hashes, not a cryptographic family. They are allowed to collide on eight keys. They are supposed to be capable of colliding, because a demonstration that never collides cannot show you the minimum earning its keep. If your hash sends all eight roots to eight different columns, you did not build a sketch. You built a lookup table and dressed it as a hash. The costume fails the moment the ninth symbol appears, and it fails the pedagogical moment even earlier, because the clean row never has to save you. Choose hashes that can overlap, watch a cell inflate, and watch a different row keep the minimum honest.

Compute the grid’s raw size so “small” is a count. Depth two, width four, eight counters. Depth four, width eight, thirty-two counters. Either one can sit on a slide. Neither one is a reason to announce a numerical epsilon. The next beat puts epsilon and delta into the width and the depth with a formula, and then tells you the lab’s grid is too small to cash it. Holding that sentence until the formula arrives is fine. What you hold now is the mechanism those parameters are buying. Width is how many columns a hash spreads into. Depth is how many independent chances you have that some row stayed clean enough for the minimum to be tight. Spread and repetition. Not a cryptographic brand, and not a second copy of the tape.

A query for B, in the picture where the rows separate A and B in row one and join them in row zero, returns the minimum of B’s collided cell and B’s clean cell. The collided cell reads eight. The clean cell reads three. The minimum is three, which is B’s truth. The same collision that threatened A threatened B, and the same kind of rescue saved B. A query is per symbol. You do not return one minimum for the whole row. You return the minimum of the cells that symbol maps to. Asking for A and asking for B are two queries. They may share a dirty cell and still have different answers, five and three, because their clean cells differ.

You leave the beat with a grid you can update by hand and a floor you can defend without the sizing formula. One increment per row per arrival. Query is the minimum. Nonnegative updates imply the minimum is at least the true count. Five and three colliding in one row and not in the other produce a minimum of five for the symbol whose truth is five. Colliding in both rows produces eight, still at least five. Six arrivals move the floor to six. A decrement can move a cell to four and the floor collapses. Eight keys with a collision-free hash are a costume. The lab would rather show you the dirty cell and the clean row that saves the minimum.

[[BEAT 1]]
The bound, with the parameters visible, is the part you do not get to wave at the picture. Set the width to the ceiling of e divided by epsilon, and set the depth to the ceiling of the natural logarithm of one divided by delta. Then the estimate is at most the truth plus epsilon times the ell-one norm of the frequency vector, with probability at least one minus delta. For positive unit updates, that ell-one norm is the length of the stream. The lab’s grid is too small to cash this bound. It is on the board to show the one-sided error, not to claim an epsilon. Width buys a smaller additive error. Depth buys a smaller failure probability. A picture with a fixed handful of cells is not a calibrated pair.

e here is the base of the natural logarithm, a little more than two and seven tenths. You need a value only because you are about to take a ceiling, and the ceiling cares which side of an integer you are on. Take epsilon equal to one tenth. e divided by one tenth is ten times e, a little more than twenty-seven point one eight. The ceiling of a number that sits between twenty-seven and twenty-eight is twenty-eight. So the width the formula asks for is twenty-eight. Take delta equal to one hundredth. One divided by delta is one hundred. The natural logarithm of one hundred is a little more than four point six. The ceiling of that value is five. So the depth the formula asks for is five. A five-by-twenty-eight grid has one hundred forty counters. That is the sketch the bound is talking about, for this epsilon and this delta. It is not the two-by-four picture from the last beat, and you must not recite “one tenth” while pointing at four columns.

The error those parameters buy is additive and scaled by the length. Let the stream contain one thousand positive unit updates. The ell-one norm is one thousand. Epsilon times that norm is one tenth of one thousand, which is one hundred. The claim is: the estimate is at most the truth plus one hundred, with probability at least ninety-nine hundredths, because one minus one hundredth is ninety-nine hundredths. If the truth of a symbol is five, the estimate is at most one hundred five on a good draw, and it is still at least five because updates were nonnegative. The gap between five and one hundred five is wide. It is what one tenth of a thousand-long tape looks like. If you needed a tighter additive gap, you chose the wrong epsilon for that tape, or you chose a point query the tape is too long to support at that epsilon. The formula did not fail. The parameter did what you asked.

Change one input. Keep delta at one hundredth and the length at one thousand, and change epsilon from one tenth to one twentieth. e divided by one twentieth is twenty times e, a little more than fifty-four point three. The ceiling is fifty-five. The width moves from twenty-eight to fifty-five. The additive budget becomes one twentieth of one thousand, which is fifty. A truth of five is now estimated by at most fifty-five, with probability at least ninety-nine hundredths, on this sizing. Depth stays five, because delta did not move. You bought the tighter additive term with width, which is the slide’s sentence that width buys a smaller additive error. You did not buy it by hoping the minimum would be kinder. Fifty-five columns is the purchase. Four columns is not a discounted version of the same purchase.

Change the other input, separately, so you do not always turn the same knob. Keep epsilon at one tenth, so the width stays twenty-eight and the additive term on a tape of one thousand stays one hundred. Change delta from one hundredth to one twentieth. One divided by one twentieth is twenty. The natural logarithm of twenty is a little under three, just shy of three if you use the ordinary value. The ceiling of a number that is just under three is three. So the depth drops from five to three. You are accepting a larger failure probability, one twentieth instead of one hundredth, and the formula lets you keep fewer rows. One minus one twentieth is nineteen twentieths, or ninety-five hundredths. The probability statement got weaker, and the grid got shallower. Rows are the currency you spend to shrink the failure probability. Spending fewer rows buys you a worse delta, not a better one. If you wanted the failure probability to shrink, you would raise the depth, not admire a deep-looking drawing.

You might ask whether one hundred forty counters, five times twenty-eight, are “sublinear” when the tape has length one thousand. They are smaller than one thousand, and the more important comparison is that they did not depend on one thousand. They depended on epsilon and delta. If the tape grows to one million positive unit updates and you keep epsilon at one tenth and delta at one hundredth, the width stays twenty-eight and the depth stays five. The space stays one hundred forty counters. The additive term grows, because epsilon times the length becomes one tenth of one million, which is one hundred thousand. The estimate is at most the truth plus one hundred thousand, with probability at least ninety-nine hundredths. Same sketch, looser absolute slack, because the slack tracks the ell-one norm and the norm tracked the tape. If that slack is useless to you, you tighten epsilon, which widens the grid, and you say the new width out loud. You do not keep twenty-eight columns and advertise the old epsilon against the new length.

What the bound does not mean is that every query on the five-by-twenty-eight grid is inside the slack. The probability is at least one minus delta, here ninety-nine hundredths. There is a budgeted chance, one hundredth, that a query is worse than truth plus epsilon times the length. A single bad query is not a refutation. A systematic miss, on a grid that is not the grid the formula sized, is not a refutation either. It is a different object. The two-by-four lab, eight counters, was never five by twenty-eight. Pointing at a collision in the lab and announcing that epsilon has failed is a category error. The lab did not claim epsilon. The notes say the grid is too small to cash the bound, and the slides say the lab grid is a picture, not a calibrated pair. Quote the overestimate as one-sided. Do not quote it as one tenth.

The approximation written with a tilde, width about e over epsilon and depth about the natural log of one over delta, is the same sizing with the ceilings left implicit. You use the ceilings when you allocate, because you cannot allocate a fraction of a column. Twenty-seven point one eight columns is not a width. Twenty-eight is. Four point six rows is not a depth. Five is. The tilde form is how you remember which parameter serves which Greek letter. The ceiling form is how you build the array. Forgetting the ceiling and allocating twenty-seven because you truncated will not satisfy the hypothesis the bound used. The theorem’s width is a ceiling, not a floor.

Walk a short tape through the same parameters so the additive term is not always one hundred. Epsilon one tenth, delta one hundredth, width twenty-eight, depth five. Let the tape be the lab’s opening, the same symbol five times, and nothing else. The length is five. Epsilon times the length is one half. The bound says the estimate is at most the truth plus one half, with probability at least ninety-nine hundredths. The truth is five. Truth plus one half is five and a half. Counts here are integers, and the sketch’s cells are integers, so an integer estimate at most five and a half is an estimate of at most five. Combined with the one-sided floor, the estimate is exactly five on a good draw. That is a strong conclusion, and it depends on the tape being length five, not on the lab’s tiny width. A five-by-twenty-eight sketch can cash that statement. A two-by-four picture cannot, even if on this particular five it happens to print five. Happening to print five is the audit. The half-unit slack is the bound. Do not transfer the bound onto the picture because both returned five.

If the five arrivals are followed by a mix and the length becomes, say, five hundred, epsilon one tenth times five hundred is fifty. A symbol whose truth is five is then bounded by fifty-five on a good draw, not by five and a half. The same sketch, the same epsilon, a longer tape, a larger additive term. People hear “epsilon equals one tenth” and think ten percent of the point frequency. That is not what was stated. The slack is epsilon times the ell-one norm of the whole stream, not epsilon times the truth of the symbol. Five plus one tenth of five would be five and a half even on the long tape. The theorem does not say that. It says five plus one tenth of the length. On a length of five hundred, that is fifty, and the cap is fifty-five. Relative to a rare symbol, the additive guarantee can be many times the truth. That is why heavy hitters, symbols that are a real fraction of the length, are the queries where an additive epsilon times the length looks like a relative error you might tolerate. A rare symbol can be drowned by a legal error term. The estimate remains at least the truth. It may sit far above it and still satisfy the bound. If your product needs rare-symbol precision, this sizing is the wrong instrument, or this epsilon is too coarse for the length you have.

You might also ask whether the natural logarithm can be swapped for a logarithm in another base if you adjust the constant. The formula as the lecture writes it uses the natural logarithm, paired with e in the width. e and the natural log are a matched pair in the analysis. Replacing the natural log with a base-ten log, and leaving the depth as the ceiling of that smaller number, shrinks the depth and drops the hypothesis. Log base ten of one hundred is two, and the ceiling of two is two, against the five you got from the natural log. Two rows are not the depth this delta asked for under the stated formula. If a derivation elsewhere uses a different base, it carries a different constant in front. You do not mix the e from the width with an unmatched log in the depth. The lecture’s pair is width ceiling of e over epsilon, depth ceiling of the natural log of one over delta. Speak that pair, or speak the tilde form, and do not improvise a third.

A negative update still destroys the floor, and the sized bound does not resurrect it. The probability statement is an upper bound, truth plus the slack, and it sits on top of an estimator that is supposed to be at least the truth. If a decrement drives a cell below the truth, you can violate the floor on every draw, which is a failure mode outside the one-hundredth you budgeted. Budgeted failure is an unlucky hash. An unbudgeted failure is an update the proof excluded. The notes are direct: the moment you allow decrements, a cell can fall below the truth and the argument is gone. Width twenty-eight and depth five do not grant an exception.

Say the sized example once, cleanly, as the thing you would write next to a real allocation. Epsilon one tenth, delta one hundredth, width twenty-eight, depth five, one hundred forty counters. On a stream of one thousand unit increments, the estimate is at most the true point frequency plus one hundred, with probability at least ninety-nine hundredths, and at least the true frequency on every draw if you never decremented. Change epsilon to one twentieth and the width becomes fifty-five, the additive term on that stream becomes fifty, and the depth stays five. Change delta to one twentieth instead and the depth becomes three while the width stays twenty-eight. The two-by-four board with a truth of five and a collided cell of eight shows the minimum and the floor. It does not show one tenth, and you do not say that it does.

[[BEAT 2]]
Hashes are part of the algorithm. What this lab actually hashes with is a tiny linear map, not a family built for cryptography. Collisions are the point. A hash that never collides on eight keys is a lookup table in a costume. You should be able to run one of those tiny maps by hand, see which keys share a bucket, and predict the minimum before you look at the board. If you cannot, the grid is a picture of boxes and the hash is a rumor.

A linear hash, of the modest kind this lab is pointing at, sends a key to a column by a multiply, an add, and a remainder modulo the width. It is not a cryptographic construction, and you should not talk about it as if it were one. Take width four, the picture width, and number the eight roots from zero through seven so the arithmetic is visible. Let the first row send key x to x modulo four. Zero and four land in column zero. One and five land in column one. Two and six land in column two. Three and seven land in column three. Four pairs, forced by eight keys and four columns. Let the second row send x to three x plus one, modulo four. Key zero goes to one. Key one goes to zero, because three plus one is four, and four modulo four is zero. Key two goes to three, because six plus one is seven, and seven modulo four is three. Key three goes to two, because nine plus one is ten, and ten modulo four is two. Key four goes to one, the same column as key zero. Key five goes to zero, the same column as key one. Key six goes to three, with key two. Key seven goes to two, with key three. So this second row collides in the same pairs the first row did. Two rows, and this particular choice of linear maps did not separate zero from four. The minimum will not be rescued for that pair, and that is a legal outcome of a tiny hash, not a bug in the minimum.

Stream five arrivals of key zero and three arrivals of key four, the pair that collides in both rows. Every arrival of either key increments row zero’s column zero, and every arrival increments row one’s column one. Both cells read eight. The query for key zero takes the minimum of eight and eight, which is eight. Key zero really arrived five times. Eight is an overestimate by three, which is exactly key four’s count, because every one of key four’s arrivals landed in both of key zero’s cells. The query for key four also returns eight, against a truth of three. Both estimates sit above their truths. The sketch is one-sided and, on this hash, not tight. You do not repair it by switching to a cryptographic name while keeping width four. Eight keys into four columns collide by the pigeonhole principle, cryptographic or not. A family can randomize which pairs collide. It cannot give eight keys eight private columns inside a width of four.

Change one input. Keep the two linear maps and the width, and replace key four’s three arrivals with three arrivals of key one. Key zero and key one do not share a column in row zero: zero goes to column zero, one goes to column one. They do not share a column in row one either: zero goes to column one, one goes to column zero. Five arrivals of key zero leave five in row zero column zero, and five in row one column one. Three arrivals of key one leave three in the other cell of each row. The minimum for key zero is the minimum of five and five, which is five. The minimum for key one is three. The same style of hash, the same width, a different partner, and the estimate meets the truth because the partner missed both cells. Collisions are the point, including the collisions that do not happen to hit the key you queried. A demonstration in which every pair misses is the costume. This pair missed. The earlier pair, zero and four, did not. You want a lab in which both kinds can occur.

Add one arrival of key four on top of the clean picture, so a single colliding update has a visible cost. Before that arrival, key zero’s estimate is five. Key four maps to the same cells as key zero in both rows. One arrival adds one to each of those cells. They read six and six. The minimum becomes six. The truth of key zero is still five. The overestimate is one, equal to the number of colliding arrivals that hit every row’s cell. If a third row used a different linear map that sent key four somewhere else, that third row’s cell would still read five, and the minimum would return to five. The depth would have bought a clean look. The two-row toy did not have that third map. You can see the purchase in one extra row without pretending two-by-four has become a calibrated epsilon.

You might ask whether you should replace the linear maps with a cryptographic hash so the eight roots stop colliding and the estimate stops printing eight. On width four, they will not stop. There is nowhere to put eight private columns. On a width large enough to hold them, for example the width twenty-eight you sized for epsilon one tenth, a hash that sends all eight roots to different columns never collides on this toy. The lecture’s sentence still applies. That hash is a lookup table in a costume, relative to an alphabet of eight. The estimate will match the truth because you built a direct address table for a tiny alphabet, which you were already allowed to do honestly by keeping eight counters and calling it a histogram. The costume is claiming you tested the sketch. You tested the case the analysis does not worry about. The algorithm does not get easier when the alphabet grows past the width. Your audit gets harder, because you can no longer see every collision by eye. A cryptographic family is about how you model the hashes in a proof, not about a permission slip to skip collisions on the demo. The lab’s choice of tiny linear hashes is so the collision stays arithmetic, like three x plus one modulo four, rather than a digest you cannot redo on paper.

What “collisions are the point” does not mean is that a broken hash is a virtue, or that any map modulo w will do in a real deployment of the sized bound. The bound, width the ceiling of e over epsilon and depth the ceiling of the natural log of one over delta, is a statement about hashes that behave well enough for the analysis, not about the first linear coefficients you wrote down. The two maps above failed to separate zero from four in either row. A sized sketch with a bad family can miss its delta. The lab is allowed to use tiny maps because it is not cashing epsilon. You are not allowed to cite the lab’s maps as the family in the theorem. What the costume sentence also does not mean is that every collision-free run on eight keys is dishonest storage. If you meant to store eight counters, say so. Exact histograms are allowed when the alphabet is tiny. The dishonest move is to store them and call the result evidence about a count-min bound.

Compute a query that shares only one row, so the minimum’s rescue is a single number you can point at. Keep width four. Keep row zero as x modulo four. Change the second row’s coefficients, one input, from three x plus one to x plus one, modulo four. Key zero in row zero lands in column zero. Key zero in the new row one lands in column one. Key four in row zero lands in column zero, a collision with key zero. Key four in row one lands in four plus one, modulo four, which is one, also a collision with key zero. That particular change did not split them. Try key two against key zero. Row zero sends key two to column two, not column zero. The new row one sends key two to three, and key zero to one, different columns. So key zero and key two collide in neither row under row zero’s map together with this new row. Five arrivals of key zero and three of key two: minimum five for key zero. Now bring back a partial collision with a third key, key four, one arrival, which hits both of key zero’s cells under these two maps. Cells go from five to six. Minimum six. To see a one-row collision you need a key that hits one cell and misses the other. Key one: row zero sends key one to column one, while key zero is in column zero, so row zero misses. The new row one sends key one to two, and key zero to one, so row one also misses. Key five: row zero sends five to column one, a miss against zero’s column zero. New row one sends five to six modulo four, which is two, and key zero is in column one, a miss. Key six: row zero sends six to column two, a miss. Row one sends six to seven modulo four, which is three, and key zero is in column one, a miss.

Key three against the new maps: row zero sends three to column three, miss. Row one sends three to four modulo four, which is zero, while key zero sits in column one, miss. The additive map x plus one modulo four is a rotation of x modulo four. It collides in the same pattern, shifted. Of course it never gives you a one-row collision between a key and the key four away, because adding one shifts both. That is a useful failure of a tiny linear family: related maps can preserve the same pairs. The lesson’s insistence that each row has its own hash is not satisfied by writing the same collision pattern twice with a cosmetic offset. Own hash means a chance of an independent bucket, not a second copy of the first remainder. When you pick the lab’s linear coefficients, check a pair by hand. If every pair that collides in row zero collides in row one, the minimum has nothing to discard, and you have built the eight-and-eight outcome on purpose.

Try coefficients that do split zero and four, so the rescue is visible as arithmetic and not as a wish. Width four. Row zero remains x modulo four, so zero and four share column zero. Row one sends x to two x plus one, modulo four. Zero lands in column one. Key four goes to eight plus one, which is nine, and nine modulo four is one. Still together. Two times four is eight, and eight is zero modulo four, so two x does not move key four relative to key zero when the width is four. Even multipliers and power-of-two widths are a classic way to lose a bit. Change the width, not the story, to five, which is not the lab’s claim of a calibrated grid and is only a place to watch a linear map separate a pair. Row zero: x modulo five. Zero stays in zero, four stays in four, no collision. That is too kind. Use keys zero and five. Five modulo five is zero, so row zero collides. Row one: two x plus one, modulo five. Zero lands in column one again. Key five goes to ten plus one, eleven, modulo five is one. Still a collision, because five is a multiple of the width and two times five is also a multiple of five. The even-multiplier issue was not the whole story. A key that differs by the width will hit the same column under any map of the form a x plus b modulo the width, because a times the width is a multiple of the width. Keys zero and five are the same key as far as a width-five linear hash is concerned. They always collide, in every row, for every a and b. The minimum cannot be rescued by depth if every row is a function of x modulo w and the two keys are congruent modulo w.

That last observation is the real content of “hashes are part of the algorithm,” and it is why a costume that never collides on eight keys has to use the keys themselves, not only their residues in a tiny width. If your hash ignores everything except x modulo w, then all keys that share a residue are the same key forever. Distinct futures roots have to be distinct inputs to the hash, and the hash has to be able to send them to different columns. A linear map on a key that is already a residue modulo w cannot. Feed the root’s identity, not a pre-folded bucket, into each row’s hash. Then ask whether those identities collide. Zero and four collided under x modulo four. They need not collide under a different function of the full identity. Depth is a set of chances at a different function, not a stack of copies of one remainder.

What this does not mean is that you should design a hash that avoids collisions for the eight roots and then stop. Avoiding them on the toy makes the estimate exact and the demo theater, in the sense the first lesson used that word: if you cannot see a collision, you cannot see the minimum earn its place. The right demo collision is the one you can audit. Five arrivals of one root, three of another, one shared bucket in a single row, a clean bucket in another row, minimum equal to five. The wrong demo is eight private columns and a speech about probability. The wrong demo in the other direction is two identical remainder maps and a minimum that always includes every collision. You are looking for the middle, where a dirty cell inflates and a different row stays clean, which is the lab brief in one line. Watch one cell inflate because two symbols share a bucket. The row that does not collide keeps the minimum honest.

Put the sized parameters beside a hash that is merely linear and tiny, so nobody carries four columns into the theorem. Epsilon one tenth gave width twenty-eight. Delta one hundredth gave depth five. Those one hundred forty cells assume a hash behavior the bound can use. A hand-checked linear map on eight keys is how you learn to update and query. It is not a witness that your probability is ninety-nine hundredths. If the hand check shows a collision in every row for the symbol you care about, the estimate will sit above the truth by the collision mass, and the one-sided claim still holds, and the epsilon claim was never on offer. If a later implementation uses a family you can actually analyze, you re-check the width and the depth against e over epsilon and the natural log of one over delta, and you re-check that updates are nonnegative. Then the upper bound is truth plus epsilon times the length, with probability at least one minus delta. The hand check does not get promoted. It stays the way you know the minimum is the query, and the way you know a costume when you see one.

A decrement, once more, against the linear map, so the floor’s failure is tied to a cell you named. Width four, row zero is x modulo four, five arrivals of key zero, three of key one, estimate five, as computed when those keys missed each other. Subtract one from key zero’s cells, a quiet negative update. Row zero column zero falls from five to four. Row one, wherever key zero landed, falls from five to four if it had only those five. The minimum falls to four. The truth is still five. Four is below five. The lab is broken if it shows you that number as a count-min estimate of a nonnegative stream. The break is local and arithmetic. It does not require a long tape, and it does not require you to doubt the sizing formula. The sizing formula never applied to a cell you were willing to decrement.

You can close by narrating one honest toy update and one honest refusal. Honest toy: eight roots, tiny linear hashes, a shared bucket in one row, a private bucket in another, five true arrivals, a minimum of five, an inflated sibling cell you can add by hand from the colliding partner’s three. Honest refusal: you will not call four columns an epsilon of one tenth, you will not call a collision-free map on those eight roots evidence of the bound, and you will not call a cryptographic label a cure for a width that is smaller than the set of keys you insisted on separating. The grid counts. The minimum is the query. The hashes decide which counts share a cell. All three are the algorithm, and only the sized three, with hashes the analysis can stand on, and with no quiet negative updates, cash the probability.
