The batching window is the time the server holds inputs so it can run them together. Throughput loves batches. Latency hates them. The idea in this block is that reproducibility is a pin, not a vibe. A model card names data, code, and metrics at a commit. Drift is a change in a distribution you specified. If you did not specify the feature distribution, you cannot announce that it drifted.

Read the model card as a set of names that can be pointed at. Data, at a commit, means you can say which data produced the fit. Code, at a commit, means you can say which program produced the fit. Metrics, at a commit, means you can say which numbers were computed, on which data, by which program. A card that says the model works, without those three pins, is a vibe. You cannot regenerate it, and you cannot tell a later change from a later story. The commit is the pin. A description that floats free of a commit can be edited until it matches whatever the model is doing now. That edit is not reproducibility. It is a rewrite.

Drift is narrower than disappointment. Drift is a change in a distribution you specified. The specification comes first. You write down the feature distribution you will compare against, and you write it down before you deploy. A threshold without a reference is a mood. If the share of missing values, or the mean of a feature, or whatever you actually specified, moves past the threshold relative to that reference, you have an announcement you can defend. If you specified nothing, the sentence "it drifted" has no subject. Retrain is an action. It is not the definition of drift. You can retrain because you drifted, or because you changed the objective, or because the card was wrong. Those are different reasons. The action does not define the word.
